## STUDY-003 — 피처와 Brier Score 기초 이해

### 피처

피처는 투수가 아니라 영어 `Feature`를 한글로 읽은 말이다. 모델이 정답을 예측할 때 참고하는 입력 정보다.

예시:

- 볼 카운트
- 스트라이크 카운트
- 주자 상황
- 투수의 과거 성공률
- 최근 경기 기록

`control_success`는 맞혀야 하는 정답이므로 피처가 아니라 Target이다.

### 피처 생성

기존 입력을 조합하거나 표현을 바꿔 모델이 패턴을 이해하기 쉬운 새로운 입력을 만드는 작업이다.

예시:

- 3볼 2스트라이크를 `is_full_count`로 표현
- 투수와 타자의 좌우 유형이 같으면 `same_hand = 1`
- 투수 성공률과 타자 상대 성공률의 차이 계산

새 피처는 반드시 현재 투구가 시작되기 전에 알 수 있는 정보로 만들어야 한다.

### Brier Score

```text
Brier Score = mean((예측 확률 - 실제 정답)²)
```

- 실제 정답은 성공 1, 실패 0이다.
- Brier Score는 낮을수록 좋다.
- 틀린 결과를 지나치게 확신하면 오차가 크게 증가한다.
- 정확도와 달리 예측 확률의 품질을 평가한다.

예를 들어 실제 정답이 1일 때:

- 예측 0.8 → 오차 `(0.8 - 1)² = 0.04`
- 예측 0.2 → 오차 `(0.2 - 1)² = 0.64`

### Brier Skill Score

모델의 Brier Score를 평가 데이터의 평균 제구율만 예측하는 기준 모델과 비교한다.

- 원래 Brier Score는 낮을수록 좋다.
- 대회 Brier Skill Score는 높을수록 좋다.
- 평균 제구율만 예측하는 것보다 나아야 양수 점수를 얻을 수 있다.

## STUDY-004 — 앙상블, 확률 보정과 네이티브 모델 형식

### 공부하게 된 이유

EXP-013에서 CatBoost와 LightGBM의 예측 확률을 섞고 선형 보정을 적용했으며, 로컬 학습 환경과 평가 서버의 Python 버전이 달라 모델 저장 방식도 함께 점검했다.

### 공부한 내용

- 앙상블은 여러 모델의 예측을 결합해 한 모델에만 존재하는 오차를 줄이는 방법이다.
- 확률 가중 평균에서는 각 모델의 비중 합을 1로 두고 예측 확률을 혼합할 수 있다.
- 확률 보정은 분류 결과를 바꾸는 작업이 아니라 예측한 확률의 크기가 실제 발생 빈도와 더 잘 맞도록 조정하는 작업이다.
- 검증 데이터로 앙상블 가중치와 보정 계수를 선택하면 그 검증 점수가 낙관적으로 보일 수 있으므로 다른 시간 구간에서도 확인해야 한다.
- scikit-learn pickle은 저장·로드 환경의 버전 차이에 민감할 수 있다.
- CatBoost `.cbm`과 LightGBM `.txt`처럼 라이브러리의 네이티브 모델 형식을 사용하면 Python 객체 pickle에 대한 의존을 줄일 수 있다.

### 프로젝트에 적용한 방법

- EXP-013에서 CatBoost 0.28719567, LightGBM 0.71280433의 가중 평균을 사용했다.
- 가중 평균에 `1.12708208 × p - 0.07336118` 선형 보정을 적용하고 결과를 0~1로 제한했다.
- 최종 모델은 `.cbm`과 `.txt` 형식으로 저장하고 제출용 `requirements.txt`에는 두 라이브러리 버전을 고정했다.

### 다음 학습

- 다른 검증 시즌에서도 같은 가중치와 보정식이 유효한지 확인한다.
- 보정 전·후 calibration curve와 Brier Score를 비교한다.

## STUDY-005 — 시간축 검증과 확률 보정의 일반화

### 공부하게 된 이유

EXP-014의 동일한 LightGBM 구성이 2024년에는 보정 후 Skill Score `780.4741206669407`을 기록했지만, 2023년에는 `40.4545039712767`에 그쳤다. 한 시즌 검증 결과만으로 다음 시즌을 선택하는 위험을 정리할 필요가 있었다.

### 공부한 내용

- 시간 데이터에서는 랜덤 분할뿐 아니라 마지막 한 시즌만 사용하는 검증도 특정 시즌 변화에 과도하게 맞을 수 있다.
- 검증 정답으로 affine scale과 intercept를 직접 구하면 그 시즌의 평균 성공률과 확률 범위에 맞춰져 같은 검증 점수가 낙관적으로 보일 수 있다.
- 시간 감쇠는 최근 데이터에 더 큰 비중을 주지만, 최근 시즌의 변화가 다음 시즌에도 이어진다는 보장이 없으므로 자동으로 일반화 성능을 높이지 않는다.
- 선수 ID나 과거 Target 통계는 검증 시점 이전 값만 사용하더라도 표본 부족과 선수 구성 변화 때문에 다음 시즌에서 불안정할 수 있다.
- 여러 rolling 시즌에서 방향이 일관된 변경을 우선하고, 보정 계수도 이전 시즌에서 결정해 다음 시즌에 평가해야 한다.

### 프로젝트에 적용할 방법

- 2022·2023·2024를 각각 검증 시즌으로 두는 rolling 평가를 만든다.
- 모델 선택과 확률 보정 평가에 같은 시즌 정답을 중복 사용하지 않는다.
- 평균 점수뿐 아니라 시즌별 최저 성능과 Brier Score 방향을 함께 본다.
- 공식 `asof_*` 피처가 제공하는 기준 확률의 잔차를 예측하는 방법을 검토한다.

### 다음 학습

- rolling-origin 평가에서 모델과 보정 계수를 선택하는 방법
- 선수 표본 수 구간별 calibration curve
- 선형 보정, sigmoid, isotonic 보정의 시간 일반화 비교

## STUDY-006 — 행별 현재 시즌 복원과 constrained residual

### 공부하게 된 이유

EXP-013 구조는 2022에서는 강했지만 2023 성공률 급락에서 raw Skill `-1303.57`로 무너졌다. 최근 시즌 모델은 2024에서 좋아도 같은 충격을 미리 알 수 없으므로, 분포 수준과 상황별 순위 효과를 분리할 필요가 있었다.

### 공부한 내용

- 공식 경력 누적 as-of 값과 학습 데이터의 직전 시즌 종료값의 차이로 현재 시즌 누적을 행별 복원할 수 있다.
- 이 방법은 평가 데이터의 다른 행을 집계하지 않으므로 대회 독립 예측 규칙을 지킨다.
- Brier residual의 시즌 평균을 제거하면 모델은 시즌 전체 수준보다 상황별 상대 효과를 주로 학습한다.
- 최근 모델을 전부 신뢰하기보다 안정적인 계층적 기준값에 제한된 비중만 더하면 구조 단절 최저 성능을 보호할 수 있다.
- 보정 계수를 같은 fold에서 맞추지 않고 다음 fold로 넘겼을 때 성능이 나빠지면 identity가 더 정직한 선택이다.

### 프로젝트에 적용한 방법

- 2022·2023·2024 rolling-origin과 2021 warm-up OOF를 만들었다.
- 현재 시즌 투수·타자 성공률을 표본 수에 따라 shrink했다.
- 과거 3시즌 그룹 효과와 직전 1시즌 LightGBM residual을 결합했다.
- residual 모델 비중을 15%로 제한했다.
- 이전 fold 평균 편향 보정은 2023 최저 성능을 낮춰 최종에서 제외했다.

### Public 제출 후 확인한 내용

- 2025 Public `895.8368767677`이 EXP-013의 `935.8108097065`보다 낮아, rolling 평균 개선만으로 2025 일반화를 판단할 수 없음을 확인했다.
- 2022의 높은 Skill이 3시즌 평균을 끌어올렸지만 최신 2023·2024 Skill은 각각 `769.85`, `795.28`이었다. 평균과 함께 최신 시즌 및 최저 시즌에 선택 제약을 두어야 한다.
- 2024에서 확인한 현재 시즌 표본 `0~19` 구간 과대 예측을 작은 진단으로 취급하지 말고, 다음 모델의 핵심 위험 구간으로 평가해야 한다.

## STUDY-007 — source-season EB, low-rank 문맥과 convex oracle 상한

### 공부하게 된 이유

EXP-018은 rolling 평균은 높았지만 2023·2024와 2025 Public이 충분히 높지 않았다. 후처리와 모델 재가중을 반복하기 전에, 어떤 효과가 시간축에서 실제로 전이되는지와 현재 저장 후보의 이론적 상한을 분리해 확인할 필요가 있었다.

### 공부한 내용

- source season마다 residual 평균을 제거하고 효과 map을 독립적으로 만든 뒤 동일 가중 평균하면, 행 수가 많은 시즌이 효과를 독점하는 것을 줄일 수 있다.
- 새 시즌에서 관측되지 않은 key를 평균 분모에서 빼지 않고 0으로 포함하면, 과거 여러 시즌 중 일부에만 나타난 선수·팀 효과가 자동으로 축소된다.
- 투수×상황 효과를 24열 행렬로 두고 truncated SVD를 적용하면 세부 문맥의 공통 패턴을 낮은 rank로 공유할 수 있다.
- rank를 현재 fold 점수로 고르면 다시 낙관 편향이 생긴다. EXP-020에서는 이전 OOF fold의 최저 Skill, 평균 Skill, 낮은 rank 순서로 선택했고 2025에는 rank 6이 선택됐다.
- 같은 fold 정답까지 허용한 convex oracle은 배포 모델이 아니라 후보 집합의 낙관적 상한 감사다. 이 상한조차 2023 Skill `936.3250374376797`, 2024 Skill `880.587899179186`이면 해당 후보들을 재가중하는 것만으로 1100에 도달할 수 없다.
- 합리수 형태의 최근 rate에서 표본 분모를 행별로 복원하는 피처는 rates-only control보다 세 시즌 모두 소폭 개선했지만, 최종 후보 대비 2023 최저 성능을 높이지 못했다. 새 피처가 실제 정보를 더 담아도 시간 전이 backbone이 약하면 최종 채택 근거가 되지 않는다.
- HistGradientBoosting은 LightGBM 같은 텍스트 네이티브 형식이 없지만, 각 트리의 노드 배열을 JSON으로 내보내 NumPy 추론을 구현하고 원본 모델과 parity를 검사하면 pickle·joblib 의존성을 제거할 수 있다. 제출 패키지는 평가 이미지 기본 패키지를 재설치하지 않고 없는 LightGBM만 설치한다.
- 앙상블 branch를 각각 `[0, 1]`로 clip한 뒤 평균하는 식과, 먼저 평균하고 한 번 clip하는 식은 비선형 경계에서 같지 않다. 학습·검증·추론의 연산 순서까지 parity 대상으로 확인해야 한다.

### 프로젝트에 적용한 방법

- EXP-019에서 2021~2024 source OOF Team EB를 독립 추정하고 missing=0 동일 가중 평균했다.
- EXP-020에서 smoothing `300`, rank 후보 `2, 4, 6, 8, 12`를 rolling-origin으로 선택했다.
- 13개 frozen 후보의 convex hull에 대해 2023·2024 Skill 1100 도달 불가를 감사했다.
- EXP-021 패키지에서 batch/singleton, 행 순열, 반복 실행 parity와 CRC·구조·row_id·확률 범위를 검증했다.

### 결론

EXP-021 Public은 strict `1043.6074197937`, aggressive `1043.1871309639`로 확인됐다. 두 후보 모두 이전 최고 EXP-013보다 107점 이상 높았고, 과거 OOF만으로 선택한 strict가 최신 시즌 점수를 보고 사후 정의한 aggressive보다 `0.4202888298` 높았다. 차이는 작지만 여러 시즌 하방과 선택 절차의 독립성을 우선한 판단이 실제 결과에서도 더 안전했음을 보여 준다. 다음 개선은 기존 예측의 보정이나 재가중이 아니라 2023·2024에 함께 전이되고 과거 fold만으로 선택 가능한 새로운 행별 신호를 요구한다.

## STUDY-008 — 누적 상태 증분 label과 유용한 감독 신호의 차이

### 공부하게 된 이유

기존 예측의 convex hull 상한이 2023·2024 Skill 1100에 못 미쳐, train에 숨은 다른 투구 결과를 보조 감독으로 사용할 수 있는지 확인했다.

### 공부한 내용

- 현재 행의 누적 count와 같은 투수·시즌의 `n+1` 상태 count 차이로 현재 투구 결과를 복원할 수 있다.
- 파일 순서를 시간 순서로 가정하면 안 된다. unique `(pitcher_id, season, asof_pitcher_n)` key join을 사용해야 행 순열에 독립적이다.
- EXP-022에서는 147만 행 중 147만 행 이상에서 binary outcome을 복원했고 success mismatch가 0이어서 label 의미는 검증됐다.
- reverse와 middle은 동시에 발생할 수 있으므로 단순 multinomial 두 범주로 만들 수 없다.
- 정확하게 복원 가능한 새 label이라고 해서 최종 target에 시간 안정적으로 유용한 것은 아니다. 보조 확률 residual은 2022를 개선했지만 2023에서 기준보다 하락했다.
- same-fold 진단 ceiling도 목표에 못 미치면 weight·보정을 더 탐색하기보다 해당 표현 family를 중단하는 편이 사후 과적합을 줄인다.

### 프로젝트에 적용한 방법

- 보조 label 복원 함수에 success parity, binary delta, duplicate key, 행 순열 불변식 테스트를 추가했다.
- 보조 분류기와 Ridge는 validation season보다 과거인 source만 사용했다.
- 2022·2023·2024 각각 Skill 1100이라는 hard gate를 JSON에 기계적으로 기록했다.
- gate 실패로 final fit과 ZIP 생성을 차단했다.

### 다음 학습

- joint multiclass는 같은 시즌에서 2023 Skill `1417.94`, 2024 `1331.79`까지 표현했지만 prior-only 전이는 각각 `849.32`, `871.59`에 그쳤다.
- 같은 시즌 fit의 높은 점수는 feature resolution이 존재함을 보여 줄 뿐, 미래 시즌에서 사용할 수 있는 모델이라는 증거가 아니다.
- source-season expert를 equal/last/median/recency로 섞거나 현재 행의 source-season similarity로 gate해도 unseen season의 구조를 맞히지 못했다.
- season discriminator는 2023 행을 거의 전부 2021로, 2024 행을 거의 전부 2019로 분류했다. 과거 domain 분류 확률은 새로운 domain의 target 관계와 같은 의미가 아니다.
- row-local trend 외삽도 2023과 2024 방향이 달라 안정적이지 않았다. outcome taxonomy branch는 추가 weight 탐색 없이 중단한다.
- 확률 residual을 logit odds-ratio로 바꿔도 2023 소폭 개선과 2024 하락이 교차했다. 표현 공간보다 효과의 시간 전이가 병목이었다.
- 누적 pitchmix 표본 수와 세 구종군 rate의 다음 keyed state는 train에서 현재 투구 구종군을 정확한 one-hot으로 복원한다. 이는 현재 투구 실제 구종을 추론 피처로 쓰지 않고 보조 supervision으로만 사용할 수 있다.
- pitchmix label `1,472,832`개를 복원했지만 15-class joint model과 독립 propensity residual 모두 미래 시즌 성공률을 개선하지 못했다. 정확한 보조 label과 target 일반화 가능성은 별개의 문제다.
